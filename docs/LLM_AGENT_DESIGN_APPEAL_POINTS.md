# LLMエージェント設計力 アピールポイント集

作成日: 2026-05-06 JST

用途:
- ハッカソン発表で「ただLLMに聞いた」ではなく、LLMエージェントを設計して使いこなしていることを伝える。
- 中学生が作る素朴なシミュレーションとの差分を明確にする。
- アイデア点・技術点・実装点・誠実さを同時に拾う。

## 一言で言うと

今回の実験は、LLMを「それっぽい文章を返すキャラ」として使ったのではない。

制度、世界状態、生活制約、記憶、認知バイアスを入力し、人間がどう知覚し、感情を持ち、行動し、副作用を生むかをrowデータとして観測する設計にしている。

## 中学生版との違い

| 素朴な作り方 | 今回の作り方 |
|---|---|
| 「この政策どう思う？」とLLMに聞く | 人物属性、生活制約、世界状態、制度情報、記憶を渡して反応を観測する |
| 10人くらいの架空キャラに感想を言わせる | 若者、家族形成、次世代、補助観測など複数レイヤーでrow化する |
| 希望が上がった/下がっただけを見る | 希望、中立、注意、危険、行動、制度利用、相談、政策疲労、副作用を見る |
| 結果を直接プロンプトで誘導する | 「希望になれ」「制度を使え」と命令しない |
| 1回の回答で結論にする | stepを進め、記憶と懸念を次に持ち越す |
| いい施策を入れたら良くなる前提 | いい施策でも疲労、対象外感、財政不安が出る前提 |
| LLMの自由作文で終わる | 固定スキーマrowにして比較、集計、UI再生できる |
| 未来予測っぽく見せる | 制度反応の事前デバッグとして限界を明示する |

## アピールできる設計ポイント

### 1. LLMを「会話キャラ」ではなく「反応観測器」として使った

LLMに自由会話をさせるのではなく、属性と状況に対する反応を構造化rowとして出す観測器にした。

発表用コピー:

```text
LLMを話すキャラではなく、社会反応のセンサーとして設計しました。
```

### 2. 結果を命令せず、情報から反応させた

プロンプトでは「不安になれ」「希望を持て」「制度を使え」と命令しない。

渡すのは、本人属性、生活制約、過去記憶、世界状態、制度情報、情報環境である。

発表用コピー:

```text
感情を指定せず、生活条件と情報環境から自然に反応させています。
```

### 3. 固定するものと自由にするものを分けた

固定するもの:

- 出力形式
- 観測項目
- 分類語彙
- 時系列
- シナリオ条件
- 制度設計の有無

自由にするもの:

- 何を知覚するか
- どう感じるか
- どう動くか
- 誰が反発するか
- 誰が制度を使うか

発表用コピー:

```text
再現性のためにスキーマは固定し、創発性のために反応は固定しませんでした。
```

### 4. 人物属性を多層にした

年齢、地域、所得、雇用、住居、ケア責任、制度信頼、SNS感受性、リスク回避、自己効力感などを持たせた。

同じ政策でも、全員が同じ反応をしない。

発表用コピー:

```text
政策への反応を、平均的な国民ではなく、生活制約を持つ個人から生成しています。
```

### 5. 認知バイアスと情報環境を入れた

公的統計を見る人、SNSに強く影響される人、専門家情報に触れる人、損失回避が強い人、制度不信が強い人で受け取り方を分ける。

発表用コピー:

```text
同じ事実でも、人によって見える世界が違うことをエージェント側に入れています。
```

### 6. 記憶と持ち越し懸念を入れた

各stepで、前回の内心、行動、懸念が次に残る。

人間らしく、過去の不信や疲労が次の反応に影響する。

発表用コピー:

```text
単発の感想ではなく、過去の記憶と懸念を持ち越す時系列エージェントにしています。
```

### 7. rowデータを細かく分けた

単なる文章ではなく、次を分けて記録した。

- evaluation
- emotion
- pathway
- support
- intensity
- action_category
- action_detail
- thought
- private_talk
- social_post
- perceived_situation
- reasoning_basis
- memory_update
- carryover_concern

発表用コピー:

```text
LLMの文章を、比較可能な社会反応rowに変換しています。
```

### 8. 内心・友達会話・SNS投稿を分けた

人間は、内心、友達への本音、SNSでの発信が違う。

そこを分けたことで、制度への本当の不安、近い人への相談、表向きの反応を別々に観測できる。

発表用コピー:

```text
人間の反応を、内心・近い人への会話・公開発信に分けています。
```

### 9. 行動カテゴリを持たせた

感情だけではなく、行動を見た。

- 静観
- 情報収集
- 相談
- 生活防衛
- 回避・縮小
- 学習・就活
- 制度利用
- 参加・連帯
- 抗議・発信
- ケア継続
- 撤退

発表用コピー:

```text
希望が上がったかではなく、生活防衛から相談・制度利用へ動いたかを見ています。
```

### 10. 4分類SUMMARYで状態を読めるようにした

希望、中立、注意、危険を毎回出し、UI上で比較できるようにした。

単なるスコアではなく、マップ上で「どの層が危険側に寄るか」を見られる。

発表用コピー:

```text
心理状態を、UI上で比較できる4分類の地図にしました。
```

### 11. 子ども希望指数を別に置いた

希望全体とは別に、家族形成対象年齢の子ども希望指数を見る。

全員平均にすると見えにくい、若者・子育て世代の変化を拾う。

発表用コピー:

```text
全体の雰囲気ではなく、家族形成に関わる層の希望を別指標で見ています。
```

### 12. 副作用を第一級の観測対象にした

良い結果だけではなく、次も観測した。

- 政策疲労
- 財政不安
- 対象外感
- 手続き疲れ
- 公平感欠損
- 情報過負荷

発表用コピー:

```text
良い政策かどうかだけでなく、疲労や反発がどこで出るかを同時に見ています。
```

### 13. 「良くなるはず」を隠さず検証した

一時金だけでは政策疲労が出た。

AI自動調整 + 持続報酬 + 伴走でも、財政不安や政策疲労が残った。

都合よく希望だけが増える演出にはしていない。

発表用コピー:

```text
強い施策束でも副作用が残ることを、むしろ見せています。
```

### 14. シナリオを段階比較にした

比較基準、一時金、持続報酬、伴走支援、AI自動調整を分けて比較した。

どの要素が効いたのかを分解して見られる。

発表用コピー:

```text
一つの成功例ではなく、施策要素を分解して比較しました。
```

### 15. 伴走支援を制度導線として設計した

伴走支援は「優しい支援」ではない。

通知、予約、着金、相談、本申込、異議申立をつなぐ制度利用導線である。

発表用コピー:

```text
制度の存在ではなく、使える手順まで届くかを見ています。
```

### 16. 政策AIを閉ループに組み込んだ

政策AIは、住民rowと社会状態を見て、次の施策を生成・修正する。

ただ施策を足すのではなく、後半では束ねる、減らす、説明する、監査する方向へ寄った。

発表用コピー:

```text
政策AIを一発回答ではなく、住民反応を見て再設計する閉ループに入れました。
```

### 17. AIに「追加」だけでなく「停止・簡素化・順序変更」を許した

政策AIが毎回新しい施策を増やすだけだと、政策疲労が爆発する。

そこで、追加だけでなく、統合、停止、簡素化、通知頻度制御、異議申立、監査も出せる設計にした。

発表用コピー:

```text
AIが施策を足すだけでなく、減らす判断もできるようにしました。
```

### 18. 個人rowを社会状態へ戻した

個人の反応を、次のような社会圧力へ集約して次stepに戻す。

- withdrawal_pressure
- institution_demand_pressure
- livelihood_defense_pressure
- policy_fatigue_pressure
- fairness_gap_pressure
- fiscal_anxiety_pressure

発表用コピー:

```text
個人の感情rowを集団圧力に変換し、次の社会状態へ戻しています。
```

### 19. エージェントは「反応しない」ことも許される

全員が政治や制度に反応するわけではない。

見ないふり、生活優先、静観、情報収集だけで止まることも自然な反応として許した。

発表用コピー:

```text
全員がドラマチックに反応する前提にしていません。
```

### 20. 人間らしい未整理さを残した

きれいな政策説明ではなく、不安、迷い、怒り、諦め、条件付き希望を出すようにした。

発表用コピー:

```text
政策パンフの反応ではなく、生活者の未整理な反応を残しています。
```

### 21. UIは生成済みrowの再生にした

発表中に毎回生成するのではなく、生成済みrowをUIで再生する。

これにより、デモが安定し、同じ結果を説明できる。

発表用コピー:

```text
生成は裏で行い、発表UIでは監査可能なrowを安定再生しています。
```

### 22. UIで切り替え比較できるようにした

セレクトボックスでシナリオを切り替え、同じUIで比較できる。

比較表、SUMMARY、マップ、row詳細がつながっている。

発表用コピー:

```text
シナリオごとに別画像を作るのではなく、同じ観測面で切り替え比較できます。
```

### 23. 発話だけでなく根拠も残した

`reasoning_basis`、`perceived_situation`、`memory_update` により、なぜその反応になったかを後から追える。

発表用コピー:

```text
LLMの出力を、後から理由まで監査できる形式にしています。
```

### 24. 限界を明示した

これは現実予測ではない。
LLM観測実験であり、実社会の因果効果推定ではない。

発表用コピー:

```text
未来を当てたとは言いません。制度の受け取られ方と副作用を事前に観測するデモです。
```

### 25. 汎用化を意識した

子育て政策だけでなく、企業人事、自治体、学校、地域交通、窓口DXにも転用できる。

入力する変更案、エージェント属性、観測する反応、設計へ戻す示唆を入れ替えれば使える。

発表用コピー:

```text
これは子育て政策専用ではなく、制度変更の反応を事前に見る汎用フレームです。
```

## もっと刺さる言い方

### 設計力を見せる言い方

```text
中学生なら、LLMに「この政策どう思う？」と聞いて終わります。
今回の実験では、人物属性、生活制約、世界状態、制度情報、記憶、認知バイアスを渡し、
反応を固定スキーマのrowとして観測しています。
```

### 創発性を見せる言い方

```text
「相談者を増やせ」と命令していません。
通知、予約、着金、相談導線を置いた結果として、
生活防衛から制度利用・相談へ移るrowが観測されました。
```

### 技術点を見せる言い方

```text
LLMの自由作文をそのまま見せるのではなく、
感情、行動、内心、SNS、根拠、記憶、持ち越し懸念に分解し、
比較可能な時系列データとしてUIに載せています。
```

### 誠実さを見せる言い方

```text
強い施策を入れても、政策疲労や財政不安が残ることを隠していません。
このデモの価値は、良い結果を演出することではなく、制度の詰まりと副作用を事前に見つけることです。
```

## 審査員に刺さる評価軸

| 評価軸 | アピールする内容 |
|---|---|
| アイデア点 | 制度を実装前に、生活者の反応経路と副作用まで事前観測する |
| 技術点 | LLMを自由作文ではなく、構造化row生成器として閉ループに組み込む |
| 実装点 | シナリオ切替、SUMMARY、マップ、row詳細、政策AIログをUIで再生 |
| 独自性 | 火災避難シミュレーション的発想を、心理・制度空間へ抽象化 |
| 誠実さ | 未来予測ではなく、制度設計の事前デバッグとして限界を明示 |
| 拡張性 | 自治体、企業人事、学校、地域政策へ転用可能 |

## 最後のまとめ

今回の強みは、LLMを使ったこと自体ではない。

強みは、LLMを社会制度の反応観測器として設計し、row化し、比較し、副作用を戻し、次の施策生成に接続したこと。

つまり、LLMエージェントを「会話」ではなく「制度設計の実験装置」として使った点である。
