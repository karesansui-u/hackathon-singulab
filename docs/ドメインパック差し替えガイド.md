# ドメインパック差し替えガイド

ドメインパックは、シミュレーションの「対象領域」を定義する一式です。

今回の本線パックは [domain_packs/agi_youth_japan](../domain_packs/agi_youth_japan/) で、AGI後の日本社会における若者・家族形成・次世代の希望経路を扱っています。

## ドメインパックで差し替えるもの

| 種類 | 例 |
|---|---|
| エージェント | 若者、現役世代、国家、企業、自治体、学校、部署、住民 |
| イベント | AGI普及、雇用再編、制度変更、補助金、説明会、反発、外部ショック |
| 感情・行動辞書 | 希望、不信、政策疲労、制度利用、相談、申請、離脱、退職 |
| 評価指標 | 子ども希望指数、退職意向、制度利用率、採用魅力度、生活安定度 |
| プロンプト | 各エージェントに渡す観測条件と出力row仕様 |
| ビューア設定 | ラベル、色、分類、表示する指標 |

## 最小構成

新しいパックを作る場合、まず次の構成をそろえます。

```text
domain_packs/{your_domain}/
  domain.yaml
  data/
    youth_agents.tsv
    working_agents.tsv
    country_agents.tsv
    organization_agents.tsv
    events.tsv
    world_events.tsv
    time_schedule.tsv
    update_coefficients.tsv
  prompts/
    system_context.md
    agent_observation.md
    organization_observation.md
  scenarios/
    baseline.yaml
    stress.yaml
  viewer/
    viewer_config.yaml
```

実際にはドメインによってファイル名を変えて構いませんが、runnerやviewerが参照する列名とスキーマは合わせます。

## 差し替え手順

1. 既存パックをコピーする

```bash
cp -R domain_packs/agi_youth_japan domain_packs/company_hr_policy
```

2. `domain.yaml` を変える
   ドメイン名、対象、観測したい問い、主な評価指標を定義します。

3. エージェントを置き換える
   企業人事なら、若手社員、中堅社員、育児中社員、管理職、採用候補者、退職リスク層などを定義します。

4. イベントを置き換える
   例: 評価制度変更、AI導入、給与テーブル変更、説明会、相談窓口、異議申立、退職連鎖、採用広報。

5. 指標を置き換える
   例: 退職意向、納得感、制度理解、採用魅力度、上司信頼、チーム協力、手続き疲労。

6. プロンプトを置き換える
   「この制度は成功する」と命令せず、属性・状態・イベント・制度情報を渡して反応を出させます。

7. シナリオを作る
   `no_intervention` に相当する比較基準と、施策あり・AI調整ありの比較を作ります。

8. 小さく確認実行する
   まずは `--steps 2`, `--agent-ids` 少数で、rowが出るかを確認します。

## 企業人事制度変更へ転用する例

| AGI若者デモ | 企業人事版 |
|---|---|
| 若者・現役世代 | 若手社員・中堅社員・管理職・育児中社員 |
| 国家イベント | 市場環境・AI導入・採用競争・法規制 |
| 構造支援 | 評価制度・給与制度・育成制度・相談制度 |
| 子ども希望指数 | 退職意向・モチベーション・採用魅力度 |
| 政策疲労 | 制度疲労・説明疲れ・評価不信 |
| 対象外感 | 不公平感・置いていかれ感 |

問いの例:

```text
AI導入と評価制度変更を同時に進めるとき、
誰にどう事前説明すれば、退職意向と制度不信を抑えられるか。
```

## 自治体施策へ転用する例

| AGI若者デモ | 自治体版 |
|---|---|
| 若者・家族形成層 | 子育て世帯、高齢者、移住検討者、事業者 |
| 世界イベント | 物価、災害、人口流出、医療介護負荷 |
| 構造支援 | 補助金、窓口、交通、住居、地域参加 |
| 子ども希望指数 | 定住意向、制度利用率、相談率、参加率 |

## 品質チェック

- 比較基準があるか
- 施策ありだけでなく、施策なしも観測しているか
- 効果指標だけでなく副作用指標があるか
- 対象外感、制度疲労、手続き疲れ、不信がrowに出るか
- エージェントの属性差が反応差として出るか
- 「希望しろ」「納得しろ」と直接命令していないか
- イベントがどのstepで誰に渡ったかを `scheduled_events_used.tsv` で監査できるか
- 結果をviewerで比較できるか
