# 家族形成・子育て世代の観測設計

## 目的

この設計は、AGI/シンギュラリティ時代に「子どもを迎えたいと思える社会が残るか」を、単なる出生率ではなく、感情・行動・制度信頼・構造支援の連鎖として観測するためのもの。

見るべき対象は、従来の「現役世代」では広すぎる。今回の問いでは、次の3つのコホートを分ける。

| コホート | 見る問い | 主な時間軸 |
|---|---|---|
| 今の家族形成・子育て世代 | いま結婚・出産・子育てをどう感じ、実行/先送り/諦めへ分岐するか | 現在-5年 |
| 今の若者 | AGI移行期の未来感情を抱えたまま、10年後に家族形成期へ入ったときどう感じるか | 10-20年後 |
| 今の子ども | 大人世代の希望/諦念/制度信頼を見て育ち、15年後に若者期へ入り、20-40年後に家族形成・子育て期でどう感じるか | 15-40年後 |

## 年齢定義

発表・UIでは、個人/代表エージェントとして厚く置く主対象を **15-40歳** とし、最初の人間パネルは **0-14歳コホート8枠、15-22歳12体、23-40歳8体** に分ける。

0-14歳は、名前付き個人エージェントではなく **子どもコホート** として扱う。これは「1歳の個人に内心やSNS発信をさせる」不自然さを避け、社会の希望/不信/連帯が次世代の初期条件としてどう継承されるかを見るため。

| 年齢帯 | 位置づけ | 観測内容 |
|---|---|---|
| 0-14歳 | 子どもコホート8枠 | 大人世代の希望/不信/連帯を受け取る初期条件。個人発話rowは原則生成しない |
| 15-18歳 | 若者前期 | 進路・学習・AI時代の職業観が開いているか |
| 19-22歳 | 若者後期 | 初職・進学・負債・住居の見通しが開いているか |
| 23-29歳 | 家族形成入口 | 結婚・同居・第1子を実行できるか、先送りするか |
| 30-40歳 | 家族形成中心期 | 子育て継続、第2子、ケアとの両立をどう判断するか |
| 41-64歳 | 子育て後半・ケア期 | 新規出生判断ではなく、次世代支援・教育費・介護負荷を補助観測 |
| 65歳以上 | 現役外 | 死亡ではなく、現役/家族形成レイヤーの観測対象外 |

## 既存レイヤーとの関係

既存の `現役世代` は廃止しない。発表上の問いに合わせ、UIと分析では次のように再分類する。

| 既存層 | 新しい扱い |
|---|---|
| 若者 15-18 | 若者前期 |
| 若者 19-22 | 若者後期 |
| 若者/現役 23-40 | 今の家族形成・子育て世代 |
| 現役 41-64 | 子育て後半・ケア補助観測 |
| 65歳以上 | 非表示または高齢層へ分離 |

## 観測指標

家族形成・子育て世代では、通常の未来感情に加えて次を観測する。

| 指標 | 意味 |
|---|---|
| 結婚意向 | 誰かと生活を組む未来を望む度合い |
| 子ども意向 | 子どもを迎えたいと思う度合い |
| 子育て実行可能性 | 所得・住居・時間・支援から見た実行可能性 |
| 次世代信頼 | この社会に子どもを置けると思える度合い |
| 先送り傾向 | 本当は望むが、今は無理として延期する度合い |
| 諦め傾向 | 望みを下げ、家族形成を断念する方向の強さ |
| 共同養育期待 | パートナー・家族・地域・制度と一緒に育てられる感覚 |

## 世代交代ルール

エージェントは「永遠に同じ個人を追う」のではなく、代表コホートとして扱う。

| ルール | 内容 |
|---|---|
| 年齢更新 | `time_schedule.tsv` の相対年に合わせて現在年齢を計算する |
| 子ども期 | 0-14歳は `child_cohorts.tsv` の代表コホートで扱い、個人LLM rowを原則生成しない |
| レイヤー移行 | 23-40歳は家族形成・子育てレイヤーに表示できる |
| 現役外 | 65歳以上は現役/家族形成マップから非表示にする |
| 新世代流入 | `generation_inflow_templates.tsv` で今の子どもコホートを15歳到達タイミングごとに若者/家族形成層へ接続する |
| 記憶継承 | 前世代の希望/諦念/制度信頼を新世代の初期値へ反映する |
| 代表重み更新 | 子ども意向・子育て実行可能性が低い状態が続くと、次世代流入重みを下げる |

## 実装方針

最小実装は次の順で行う。

1. LLM生成時に `current_age` を渡す
2. rowデータに `base_age` と `current_age` を保存する
3. UIの表示年齢は `current_age` があれば優先する
4. UIフィルタに `家族形成・子育て` を追加する
5. 45歳以上/65歳以上の表示ルールを入れる
6. 次世代流入テンプレートを使って、長期ステップで新しい若者コホートを入れる

この順番にする理由は、先に新世代流入を実装すると、ID、代表重み、前世代記憶、UI検索、LLM継続状態が同時に複雑化するため。
