# ドメインパック設計と本質

## これは何の実験か

この実験は、未来を単純に当てるための予測AIではない。
本質的には、制度・施策・環境変化に対する人間集団の反応と反作用を事前に見るための、社会システムの風洞実験である。

見るべきものは、施策が意図通り効くかだけではない。

- 誰に効くか
- 誰に効かないか
- 誰が怒るか
- 誰が離脱するか
- どこで連帯が生まれるか
- どの反応が次の社会状態を悪化/改善するか
- 副作用や遅延効果がどこに出るか

このシミュレーターの価値は、「未来を一点予測すること」ではなく、見落としやすい反応経路を構造的に洗い出すことにある。

## ドメインごとの違い

企業、行政、国家、学校では、扱う主体、介入、反応、フィードバックが違う。
ただし、シミュレーターの骨格は共通化できる。

| ドメイン | 主な単位 | 介入 | 反応 | フィードバック |
|---|---|---|---|---|
| 企業 | 社員、チーム、部署 | 評価制度、報酬、AI導入、働き方 | 納得、不公平感、協力、離職 | 生産性、採用力、マネージャー負荷 |
| 行政 | 住民、事業者、自治体職員 | 給付、規制、公共サービス | 申請、反発、制度利用、信頼変化 | 予算圧、住民満足、政治圧 |
| 国家 | 国民、企業、国家主体 | 安全保障、産業政策、税制 | 不安、支持、抗議、移動、投資 | 財政、外交、社会安定 |
| 学校 | 生徒、保護者、教員 | カリキュラム、評価、進路支援 | 意欲、不安、反発、学習行動 | 学力、進路、教員負荷、校風 |

## 共通コンポーネント

毎回ドメインが違っても、品質を揃えるためには、次のコンポーネントを共通化する。

| 共通コンポーネント | 役割 |
|---|---|
| Actor / Agent | 誰が反応するか |
| Intervention | 何を変えるか |
| Context | その人が置かれた環境 |
| Perception | その人が何を知覚するか |
| Emotion / Cognition | どう感じ、どう解釈するか |
| Action | どう動くか |
| Aggregation | 個人反応が集団としてどう現れるか |
| Feedback | その反応が次の状況をどう変えるか |
| Audit | なぜそうなったか検証できるか |

作るべきものは、企業用、行政用、学校用の個別アプリではない。
ドメインパック差し替え型のシミュレーション基盤である。

```text
Simulation Core
  ├─ LLM観測
  ├─ row生成
  ├─ 集団集約
  ├─ フィードバック
  ├─ 比較
  └─ 監査

Domain Pack
  ├─ エージェント分類
  ├─ 感情辞書
  ├─ 行動辞書
  ├─ 施策辞書
  ├─ イベント辞書
  ├─ 波及チャネル
  ├─ 評価指標
  └─ 証拠/仮定
```

## 適したドメイン粒度

一番よい粒度は、施策の影響対象とフィードバック経路が見えるサイズである。

大きすぎると曖昧になる。

- 悪い例: 日本社会をよくする
- 悪い例: 会社をよくする
- 悪い例: 学校をよくする

小さすぎると波及が見えない。

- 悪い例: Aさんがどう思うか
- 悪い例: 1人の社員が転職するか

ちょうどよい粒度:

- 企業: 評価制度変更が、若手/中堅/管理職/育児中社員にどう効くか
- 行政: 住宅支援が、若者/子育て世帯/非対象者/窓口職員にどう効くか
- 学校: AI教材導入が、生徒/教員/保護者/進路選択にどう効くか
- 国家: AI産業政策が、若者/現役世代/企業/財政/外交圧力にどう効くか

## 今回の実験の優れている点

今回の実験で優れているのは、LLMを単なるチャット役にしていないところである。

重要な設計は次の通り。

1. 人を属性だけでなく、生活制約、認知傾向、制度信頼、過去記憶を持つ存在として扱う
2. 感情と行動を分けている
3. 個人の反応を集団反応へ集約している
4. 集団反応を次の社会状態へ戻している
5. LLMに命令せず、情報を渡して観測rowを作らせている
6. rowごとに、なぜそうなったかを残している
7. 施策の効果だけでなく、副作用、反発、離脱、情報過敏を見ようとしている

この設計により、単なるデモではなく、制度設計の事前検証装置として使える。

## プロダクトとしての立ち位置

このプロダクトは、自由すぎるLLMごっこではなく、制度設計・シナリオ予測に使える創発観測装置である。

LLMに「未来をそれっぽく語らせる」ことが目的ではない。
施策、制度、環境変化を情報として与えたときに、異なる属性の人々や組織がどう知覚し、どう感じ、どう動き、その反応が次の社会状態へどう戻るかを観測することが目的である。

したがって、完全に自由な生成ではなく、制約された創発を扱う。
ルールをなくすのではなく、結果を決めるルールを避け、観測を成立させるルールだけを置く。

固定してよいもの:

- ステップの進み方
- 出力rowの形式
- 感情カテゴリ・行動カテゴリ
- エージェントに渡す情報の種類
- 集団反応の集約方法
- 波及チャネル
- ログ、再現性、比較方法
- 現実データや仮定の出典

固定しすぎてはいけないもの:

- この人は必ず不安になる
- この施策では必ず希望が上がる
- 若者は必ず抗議する
- 戦争イベントなら全員悪化する
- 政策は必ず成功/失敗する

つまり、制度・環境・情報接触の条件は設計する。
しかし、感情と行動の結果は固定しない。
この境界設計が、シミュレーターとしての再現性と創発性を両立させる。

## 精度の考え方

このシミュレーターでいう精度は、未来を一点で当てる精度ではない。

重要なのは次の精度である。

- 反応経路を網羅できているか
- 属性ごとの反応差を表現できているか
- 副作用を隠さず出せているか
- なぜその結果になったか説明できるか
- 施策比較に使える形で集約できているか
- 次ステップへの反作用がモデル化されているか

したがって、発表上は「未来予測AI」と言い切らないほうがよい。
より正確には、制度案・施策案に対する人間反応と社会波及の事前検証シミュレーターである。

## ハッカソンでの説明文

このシステムは、政策や制度を実行する前に、人々がどう感じ、どう動き、その反応が社会全体にどう跳ね返るかを試すためのシミュレーターです。

企業、行政、学校、国家など、ドメインごとにエージェント、感情、行動、評価指標を差し替えることで、同じフレームで施策の効果・副作用・波及を検証できます。

今回のAGI時代の若者シミュレーションは、その最初のドメインパックです。

短い説明:

自由すぎるLLMごっこではなく、制度設計・シナリオ予測に使える創発観測装置。

別表現:

制度設計とシナリオ予測に使える、創発反応の観測装置。
