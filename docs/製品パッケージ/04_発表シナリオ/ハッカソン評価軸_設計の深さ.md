# ハッカソン評価軸 設計の深さ

このメモは、審査員に「ただテーマを変えたデモ」ではなく、課題設定、前提、エージェント、オブジェクト、観測、転用まで設計していることを伝えるための補助資料。

発表では「中学生なら」という表現は少し強く聞こえる可能性があるため、外向きには「素朴な実装なら」「最小デモなら」と言うのが安全。
内部メモとしては、浅い実装との差分を明確にするために比較する。

## 一言で言う

```text
今回の価値は、LLMに未来っぽい会話をさせたことではありません。
火災シミュレータの「空間・イベント・エージェント・行動」を、
制度設計の副作用と波及を観測する汎用フレームに抽象化したことです。
```

## 素朴な実装との差分

| 軸 | 素朴な実装なら | 今回の設計で考慮したこと | 審査員に伝える価値 |
|---|---|---|---|
| 課題 | AIで仕事がなくなるので不安、という単発テーマにする | AI、資本主義、役割喪失、制度信頼、家族形成、地域、国家圧力をつなげる | 社会課題を単発イベントではなく、構造変化として扱っている |
| 前提 | 「AIで悪くなる」「制度で良くなる」と決め打ちする | 命令ではなく、世界イベント、日本社会状態、制度介入、属性情報を入力する | LLMに結論を言わせず、反応を観測する形にしている |
| 空間 | 2Dマップに人を置くだけ | 物理空間ではなく、未来への心理・制度空間として4部屋に写像する | 火災シミュレータの空間概念を社会制度の観測空間へ抽象化している |
| エージェント | 若者を何人か置いて会話させる | 国家、組織、若者、家族形成世代、次世代コホートを分ける | 個人の感情だけでなく、外圧、実装主体、観測対象を分離している |
| 属性 | 名前と年齢だけ | 年齢、地域、所得、雇用、住居、ケア責任、SNS感受性、制度信頼、希望指数などを持つ | 同じイベントでも人によって反応が違うことを表現できる |
| オブジェクト | イベントを手書きで起こす | 世界イベント、制度イベント、組織判断、個人行動、社会フィードバックを別オブジェクトにする | 施策、外圧、反応、波及を混ぜずに検証できる |
| 感情 | 悲観/楽観だけ | 平静、不安、怒り、裏切られ感、喪失感、絶望、諦念、安心、希望、連帯感を扱い、4分類へ集約する | 感情の粒度とUIの見やすさを両立している |
| 行動 | 感情だけ表示する | 情報収集、制度利用、生活防衛、相談、学習・就活、ケア継続、撤退圧などを分ける | 「気持ち」だけでなく、次に何が起きるかまで見られる |
| 観測 | LLMの会話をその場で見る | 内心、友達との会話、SNS発信、行動、因果をrowデータに保存する | 再生、監査、比較、発表動画化ができる |
| フィードバック | 1ステップごとの紙芝居 | 個人反応を人口重みで集約し、生活防衛圧、制度要求圧、情報過敏などを次の社会状態へ戻す | 個人反応が社会全体へ跳ね返る閉ループを持つ |
| 長期性 | 直近数ステップだけ | 5年、40年、100年の時間軸を持ち、世代流入と制度記憶を見る | 短期KPIではなく、次世代に希望経路が残るかを見られる |
| 構造持続 | 「支援があれば良い」とする | 個人、家系、企業、社会、国家、自然の持続可能領域を広げる活動を価値として扱う | 資本主義の短期最適化を補完する思想がある |
| 監査・安全性 | 報酬を配ればよいとする | nat報酬、反実仮想、乖離監査、権利床、個人監視禁止、金融制約を分ける | 制度化したときの悪用、弱者の材料化、インフレまで考えている |
| 転用 | AGI若者専用で終わる | ドメインパック、辞書、イベント、エージェント、UI設定、フックを差し替える | 企業、行政、学校、自治体、地域施策にも横展開できる |
| 発表安定性 | 発表中にLLMを実行する | 事前生成したrowデータをUIで再生する | ハッカソン当日の事故を避けつつ、LLM生成の説明可能性を残す |

## 審査員向けの刺し方

### 1. 火災シミュレータの本質を抽象化した

配布された題材を単に別テーマに置き換えたのではない。

```text
火災:
物理空間でショックが起き、人が避難し、混雑や協調が起きる

今回:
心理・制度空間でショックが起き、人が不安、希望、生活防衛、制度利用へ移り、
その集団反応が次の社会状態へ戻る
```

つまり、火災の「イベント -> エージェント反応 -> 集団挙動 -> 状態変化」という骨格を、制度設計シミュレーションへ移植した。

### 2. LLMを会話生成ではなく観測器として使った

LLMに「希望を持て」「怒れ」と命令しない。
渡すのは、属性、社会状態、イベント、制度情報、過去の記憶である。

LLMからは、自由作文ではなく、次のような構造化rowを取る。

- 主感情
- 評価分類
- 内心
- 友達との会話
- SNS発信
- 行動
- 因果
- 次ステップへ持ち越す懸念

これにより、創発的な反応を残しながら、比較、再生、監査ができる。

### 3. 個人だけでなく系全体への波及を見る

個人の不安を表示するだけでは、制度設計には使いにくい。
今回の設計では、個人反応を人口重み付きで集約し、次の社会状態へ戻す。

例:

```text
不安が増える
  -> 情報収集が増える
  -> SNS不安増幅が上がる
  -> 制度要求圧が上がる
  -> 組織や国家の判断が変わる
  -> 次ステップの若者反応が変わる
```

この閉ループがあるため、「施策の直接効果」だけでなく、副作用、反発、離脱、制度要求の連鎖まで見られる。

### 4. 転用できる設計にした

今回のテーマはAGI時代の若者だが、プロダクトとしてはテーマ固定ではない。

差し替えるもの:

- エージェント属性
- イベント辞書
- 感情辞書
- 行動辞書
- 評価指標
- UI設定
- プロンプトテンプレート
- フィードバック係数

これにより、次のようなテーマにも転用できる。

| ドメイン | 例 |
|---|---|
| 企業 | 人事制度変更、AI導入、評価制度、リモートワーク |
| 行政 | 子育て支援、介護制度、地域交通、住宅政策 |
| 学校 | 校則変更、探究学習、進路支援、いじめ対策 |
| 自治体 | 移住政策、地域医療、公共施設再編 |
| コミュニティ | 部活、サークル、NPO運営 |

## 発表で使える短い台詞

```text
最小デモなら、人を置いて、イベントを起こして、会話させれば成立します。
でも制度設計に使うには、それだけでは足りません。

誰が、どんな属性で、何を見て、どう感じ、どう行動し、
その行動が次の社会状態にどう戻るのか。

今回はそこまで分解して、rowデータとして保存し、
発表ではそれを安定して再生できるようにしました。
```
