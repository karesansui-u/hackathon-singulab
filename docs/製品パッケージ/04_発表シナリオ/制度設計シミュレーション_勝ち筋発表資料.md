# 制度設計シミュレーション 勝ち筋発表資料

## 発表で一番伝えること

これは未来を当てるAIではない。

制度や施策を実行する前に、人々がどう受け取り、どう感じ、どう動き、その反応が社会や組織へどう跳ね返るかを事前に観測するためのシミュレーターである。

一言で言うなら、

```text
制度変更の事前リハーサル。
```

または、

```text
社会制度の風洞実験。
```

ハッカソンの文脈では、配布された火災シミュレーターの本質を、物理避難から制度反応へ抽象化した、と伝える。

```text
火災シミュレーター:
物理空間でショックが起き、人が避難し、混雑や協調が起きる。

今回:
心理・制度空間で社会ショックや施策が起き、人が不安、希望、生活防衛、制度利用、撤退、連帯へ移る。
その集団反応が次の社会状態へ戻る。
```

## 素朴な実装との差分

発表では「中学生なら」とは言わず、「素朴な実装なら」と言う。

### 素朴な実装なら

```text
AIで仕事がなくなる未来です。
若者キャラが不安になります。
政策を入れると希望が増えます。
地図に表示します。
```

### 今回の設計

```text
世界イベント、国家反応、日本社会状態、組織判断、
若者・家族形成世代・次世代コホートの反応を分ける。

LLMには結論を命令せず、
属性・生活制約・制度・外圧・過去記憶を渡す。

出力は会話ログではなく、
感情、行動、SNS発信、内心、因果、持ち越し懸念を持つrowデータとして保存する。

その集団反応を次の社会状態へ戻す。
```

この差分が、アイデア点と技術点の両方になる。

## 審査員に刺す説明

### アイデア点

多くの制度設計は、実施してから人々の反応を見る。
しかし本当は、実施前に次のことを知りたい。

- 誰に届くか
- 誰に届かないか
- 誰が怒るか
- 誰が離脱するか
- どこで連帯が生まれるか
- どこで不公平感が出るか
- どの順番で説明すれば反発が減るか
- どの補助策を先に置けば制度利用が増えるか

今回の作品は、その反応経路を事前に観測するための「制度設計シミュレーター」である。

### 技術点

LLMを自由会話のキャラクターとして使っていない。
条件を与えられた人物、組織、国家の反応を観測する推論器として使っている。

出力は固定スキーマのrowデータである。

- 評価分類
- 主感情
- 感情強度
- 行動カテゴリ
- 具体行動
- 内心
- 友人との会話
- SNS発信
- 知覚した状況
- 反応の根拠
- 次ステップへ残る懸念

これにより、再生、比較、監査、集約、フィードバックができる。

## 今回のデモで見せるもの

今回のドメインは、AGI時代の日本の若者・家族形成世代である。

問い:

```text
AIによって二極化する未来に、
若者や子育て世代は未来への希望を持てるのか。
子どもを持つ選択肢を失わずにいられるのか。
```

比較するrun:

| run | 見ること |
|---|---|
| 介入なし | 世界圧力、生活不安、制度不信が進むとどうなるか |
| 構造持続介入 | 住居、学び直し、ケア、役割経路があると危険域から戻るか |
| 構造持続+出産支援 | 出産一時金や休息・代替ケアが家族形成にどう効くか |
| 希望+家族形成 | 金銭支援だけでなく、希望経路、役割、非強制監査まで入れるとどう変わるか |

デモで強調する数字:

```text
介入なしでは、家族形成世代の子ども意向が大きく落ち、
危険・注意の反応が増える。

構造持続介入では、危険域からは戻る。
ただし、それだけではまだ不安が残る。

希望+家族形成パッケージまで入れると、
子どもを持つ選択肢が心理的に戻り、
良好・中立の反応が増える。
```

ここで言いたいのは、「お金を配れば解決」ではない。

重要なのは、住居、所得、休息、代替ケア、学び直し、制度信頼、非強制監査、役割経路をセットで設計しないと、人は安心して未来を選べない、ということ。

## デモ構成

発表では、デモを2つに分ける。

```text
Demo 1:
若者AGI・子育て/家族形成シミュレーション

Demo 2:
```

この順番がよい。

Demo 1で「本当に創発反応を観測できている」ことを見せる。
Demo 2で「これは一回限りのデモではなく、別の制度設計にも使える基盤になる」ことを見せる。

### Demo 1: 若者AGI・子育て/家族形成

目的:

```text
実際にシミュレーションが動き、施策によって人々の感情・行動・子ども意向が変わることを見せる。
```

見せる画面:

- 4部屋マップ
- 介入なし/構造持続/出産支援/希望+家族形成の切り替え
- 子ども意向
- 希望人数
- エージェント詳細
- 内心、友人との会話、SNS、行動、因果

話すこと:

```text
まず実例として、AGI時代の若者と家族形成世代を観測します。
AI、物価、雇用不安、制度支援が入ったとき、
若者や子育て世代が未来をどう感じ、どう動くかを見ます。
```

Demo 1で審査員に伝える価値:

- LLMエージェントがrowデータを生成している
- 感情だけではなく行動まで出している
- 介入前後を比較できる
- 子ども意向のような制度評価指標に変換できる

### Demo 2: 制度変更シミュレーション用 自動創発設計システム

目的:

```text
ユーザーが制度変更案を入力すると、
どんなエージェント、施策、観測指標、比較runで検証すべきかを自動設計できる構想を見せる。
```

見せる画面:

- シミュレーション作成スタジオ
- 問いと条件
- 施策パッケージ
- APIプレビュー
- `run_request.json`
- 比較run

話すこと:

```text
次に、この仕組みを汎用化します。
ユーザーが「こういう制度変更をしたい」と入力すると、
設計補助LLMが、対象者、施策、状態変数、副作用、観測指標を整理します。

その結果をrun_requestとして保存し、
API経由でシミュレーションジョブを作る設計です。
```

Demo 2で審査員に伝える価値:

- AGI若者専用ではない
- UIから制度設計案を作れる構想がある
- APIキーはバックエンド `.env` に置き、UIから直接LLMを叩かない
- 設計補助LLMと観測LLMを分離している
- 企業制度や自治体政策へ転用できる

## 企業制度への転用

このシミュレーターは、AGI若者専用ではない。
企業の人事制度やAI導入の事前リハーサルにも使える。

### 例: AI評価制度を導入する

企業が新しいAI評価制度を導入するとする。

普通は、導入後に問題が見える。

- 若手が監視されていると感じる
- 中堅が評価不公平を感じる
- 管理職の運用負荷が増える
- 育児中社員やケア責任者が不利になる
- 離職者が出る
- 採用候補者に警戒される
- 社内SNSや口コミで不信が広がる

このシミュレーターでは、導入前に社員タイプ別の反応を観測できる。

見られるもの:

- 若手は成長機会と見るか、監視と見るか
- 中堅は評価基準に納得するか、不公平感を持つか
- 管理職は運用できるか、負荷で壊れるか
- 育児中社員やケア責任者に不利にならないか
- どの順番で説明すると反発が減るか
- どの補助制度を先に置けば離職が減るか
- 採用候補者には魅力として伝わるか、警戒されるか

企業向けの一文:

```text
人事制度やAI導入を、社員反応・離職リスク・採用ブランドへの波及まで含めて事前検証するシミュレーターです。
```

### 企業での具体ユースケース

| テーマ | 検証できること |
|---|---|
| AI評価制度 | 納得感、不公平感、監視感、成長実感、離職リスク |
| 報酬制度変更 | 高評価者/低評価者/中堅/育児中社員の反応差 |
| リモートワーク変更 | 出社回帰への反発、チーム連携、採用ブランド |
| 生成AI導入 | 生産性向上、スキル不安、学び直し、職務再設計 |
| 管理職制度変更 | 管理職負荷、昇進意欲、若手のキャリア観 |
| 新卒採用方針 | 候補者に魅力として伝わるか、不安材料になるか |

## 自治体制度への転用

自治体の制度設計にも使える。

自治体の制度は、作れば使われるわけではない。
住民が制度を知り、信じ、申請でき、窓口が回り、非対象者の不公平感を抑えられて、初めて機能する。

### 例: 子育て・住宅支援を導入する

見られるもの:

- 対象者が制度を知覚できるか
- 申請負荷で諦めないか
- 非対象者が不公平感を持たないか
- 窓口職員に負荷が集中しないか
- どの順番で周知すると制度利用が増えるか
- どの層に先に説明すると反発が減るか
- 副作用として地域分断や制度不信が出ないか

自治体向けの一文:

```text
政策を実施する前に、住民の制度利用、不公平感、申請離脱、窓口負荷、地域への波及を事前に観測できます。
```

### 自治体での具体ユースケース

| テーマ | 検証できること |
|---|---|
| 子育て支援 | 利用率、非対象者の不公平感、申請負荷、出生非強制性 |
| 住宅支援 | 若者定着、家族形成、家賃補助への反応、財政不安 |
| 地域交通 | 高齢者、学生、通勤者、事業者の反応差 |
| 移住政策 | 既存住民との摩擦、定着可能性、仕事・住居との接続 |
| 公共施設再編 | 利用者反発、地域間不公平感、代替手段の納得感 |
| 窓口DX | 便利さ、デジタル弱者の離脱、職員負荷 |

## 「どんな施策が効果が高いか」だけではない

このシミュレーターの強みは、施策Aと施策Bの比較だけではない。

より実務的には、次の問いに答える。

- どの順番で実施すべきか
- 誰に先に説明すべきか
- 何を先に補助すべきか
- どの層が反発しやすいか
- どの副作用を事前に潰すべきか
- どのメッセージだと不信が減るか
- どの制度とセットなら利用されるか
- どのタイミングだと離職や申請離脱が減るか

企業で言えば、

```text
どういう順番で誰にどう伝えておけば、退職者が出にくいか。
採用にも効く制度変更として受け取られるか。
```

自治体で言えば、

```text
どういう順番で誰にどう伝えておけば、制度利用が進み、
不公平感や申請離脱や窓口崩壊が起きにくいか。
```

## デモの話し方

### 冒頭

```text
これは未来予測AIではありません。
制度や施策を実行する前に、人々がどう受け取り、どう動き、
その反応が社会全体へどう跳ね返るかを見るシミュレーターです。
```

### 火災シミュレーターとの接続

```text
配布された火災シミュレーターでは、
物理空間で火災が起き、人が避難します。

私はこの骨格を、制度設計に置き換えました。
心理・制度空間で社会ショックや施策が起き、
人が不安、希望、生活防衛、制度利用、撤退へ移ります。
```

### LLMの使い方

```text
LLMには「この施策で希望を持ってください」とは命令していません。
渡しているのは、年齢、地域、所得、雇用、住居、ケア責任、
制度信頼、世界イベント、社会状態、施策条件です。

その条件に対して、どう感じ、どう動くかをrowとして観測します。
```

### 結果の読み

```text
介入なしでは、家族形成世代の子ども意向が落ち、
危険・注意の反応が増えます。

構造持続介入では、危険域からは戻ります。
ただし、まだ不安は残ります。

希望+家族形成パッケージでは、
金銭支援だけでなく、住居、役割、非強制監査、制度信頼まで組み合わせることで、
子どもを持つ選択肢が心理的に戻ってきます。
```

### 転用の説明

```text
今回のAGI若者シミュレーションは、最初のドメインパックです。

同じ仕組みは、企業の人事制度変更やAI導入、
自治体の子育て支援や住宅政策にも使えます。

制度を出す前に、誰がどう反応し、どこで反発し、
どの順番で説明すべきかを事前に試せます。
```

### 締め

```text
短期KPIでは見えないものがあります。
人が未来に役割を持てるか。
壊れたときに戻れる経路があるか。
次世代が、自分にも未来があると思える制度記憶が残るか。

このシミュレーションは、そこを制度設計の対象にするための第一歩です。
```

## 想定質問と回答

### Q. これは本当に未来を予測できるのか

```text
一点予測ではありません。
制度案に対して、どういう反応経路や副作用が起こりうるかを事前に洗い出すためのものです。
```

### Q. LLMが作った物語ではないのか

```text
自由作文にはしていません。
属性、状態、イベント、制度条件を渡し、出力形式をrowに固定しています。
```


### Q. 施策の正解を出せるのか

