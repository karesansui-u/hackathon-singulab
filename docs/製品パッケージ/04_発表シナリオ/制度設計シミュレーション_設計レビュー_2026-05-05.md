# 制度設計シミュレーション 設計レビュー

作成日: 2026-05-05

## 結論

この企画は「単にLLMに未来を語らせる」より一段強い。固定した社会条件、個人属性、前ステップ記憶、政策イベントを入力し、各エージェントの知覚、感情、行動、記憶更新を観測する構造になっているため、創発性はある。

一方で、ハッカソンで技術点・アイデア点を取りにいくなら、最大のリスクは「良い結果が出るように施策を大量投入しただけ」に見えること。特に希望・家族形成パッケージは同時に見える施策イベント数が多く、比較条件の公平性を明示しないと、創発ではなく誘導に見える。

したがって、発表前に決めるべき中心論点は次の3つ。

1. 施策投入量をどう公平化するか。
2. プロンプトが希望側へ寄りすぎないよう、反応しない・届かない・対象外感が残る条件をどう明文化するか。
3. 未来イベントを「予測」ではなく「仮説シナリオ」としてどう管理するか。

## 主要所見

## 創発性の評価

創発性はある。理由は次の通り。

- エージェントごとに年齢、属性、生活制約、制度信頼、SNS感受性、前ステップ記憶が異なる。
- 同じイベントを見ても、`perceived_situation` と `reasoning_basis` が個人ごとに分岐する設計になっている。
- 出力は単なるスコアではなく、感情、行動カテゴリ、具体行動、内心、会話、SNS発信、記憶更新を持つ。
- 閉ループ実行では国、組織、個人、フィードバックの順に状態が更新される。

ただし、創発性を強く見せるには「施策を全部見せる」のではなく「同じ予算・同じ情報量・同じ実装能力の中で何が自然に立ち上がるか」を見せるほうがよい。

発表での言い方:

> このシミュレーションは、LLMに理想の未来を書かせるものではありません。制度、生活制約、情報到達、過去記憶を固定し、その条件に置かれた人がどう誤解し、期待し、反発し、動かなくなるかまで観測する制度設計の実験環境です。

## プロンプトレビュー

### 良い点

- 「本人への命令ではなく観測条件」と明記している。
- `event.direction` を命令ではなく説明ラベルとして扱わせている。
- 全員が同じ方向に動かない、情報が届かなければ反応しなくてよい、と明記している。
- きれいに整理しすぎない発話を要求しており、デモ画面の説得力につながる。

### 修正したほうがよい点

希望側の反応を許す記述は必要だが、同時に「制度があっても効かない条件」を同じ強さで書いたほうがよい。

追加候補:

```text
具体的な支援や経路が存在しても、本人がそれを知らない、対象外だと思う、手続きが重い、過去の制度不信が強い、家族ケアや住居制約で動けない、財政不安で持続しないと感じる場合は、評価や行動は大きく改善しなくてよい。
```

また、`scenario_context` は希望シナリオだけではなく、全比較シナリオで同じ構造にする。

```json
{
  "scenario_mode": "...",
  "available_policy_channels": [],
  "delivery_channels": [],
  "known_constraints": [],
  "what_is_not_available": []
}
```

これにより「出産支援のみ」には構造持続がない、「構造持続のみ」には直接出産支援がない、という比較条件がLLMにも明確になる。

## 未来イベントレビュー

未来イベントの方向性は、ハッカソンのデモとして妥当。AI/ロボ普及、雇用不安、教育費、住居、介護、地政学、エネルギー、SNS悲観、制度不信は、若者の将来感情と家族形成に効くストレス要因として自然。

ただし、現状のままだと「本当にそうなる予測」と受け取られる危険がある。特に地政学や国際情勢は日付に依存して揺れやすい。

発表と実装では次の扱いにするのがよい。

- `world_events.tsv` は予測データではなく、制度耐性を試すストレスシナリオであると明記する。
- 近未来の具体イベントは、信頼度と仮説レベルを持たせる。
- 複数の未来分岐を作る。例: 地政学緊張高 / 中 / 低、AI雇用代替高 / 中 / 低。
- 100年後までの個別イベントは細かく予測せず、制度記憶、人口構造、財政信頼、ケア基盤のような抽象度に上げる。

追加カラム候補:

```tsv
source_type	confidence	assumption_level	scenario_variant	last_reviewed
```

値の例:

```tsv
scenario_assumption	0.60	mid	case_ai_pressure_high	2026-05-05
```

## 追加で決めるべきこと

### 1. 比較条件

最低限、次の5シナリオは維持する。

- 介入なし
- 出産支援のみ
- 構造持続のみ
- 構造持続+出産支援
- 構造持続+希望・家族形成パッケージ

追加比較として、次の2つを後で足す。

- 持続通貨なし + LLMが現実的な施策を打ち続ける
- 持続通貨あり + LLMが現実的な施策を打ち続ける

ただし、この2つは施策投入量を公平化しないと、比較として弱くなる。

### 2. マイナス面と二極化の扱い

このシミュレーションで強く見せるべきなのは、政策が常に良い効果を出すことではない。むしろ、良い意図の制度でも次のような副作用が出ることを観測できる点が重要。

- 対象外になった人の反発
- 支援される人とされない人の分断
- 手続きや監査への疲労
- 財政不安や将来増税への不信
- 企業・自治体の実装負荷
- 地域差、所得差、年齢差による効果の偏り
- 「子どもを望むべき」という圧力として受け取られるリスク
- 制度をうまく使える層だけがさらに有利になるリスク

したがって、成功判定は「全員が希望になる」ではなく、次のように置くのがよい。

> マイナス面が出ない制度が優れているのではなく、マイナス面を早期に検知し、対象者別・地域別・時間順に調整できる制度が優れている。

追加指標:

- 二極化リスク
- 対象外反発
- 政策疲労
- 強制感
- 財政不安
- 実装負荷
- 受益者/非受益者ギャップ
- 若者/親世代/高齢者ギャップ
- 都市/地方ギャップ
- 所得階層別の希望格差

実装上は、各ステップで次のような集計を作る。

```tsv
step	scenario	polarization_risk	exclusion_backlash	policy_fatigue	coercion_feeling	fiscal_anxiety	implementation_load	adjustability_score
```

エージェント出力にも、将来的には次の観測項目を足す。

```json
{
  "side_effect": "対象外感/監視疲れ/財政不安/強制感/なし",
  "adjustment_request": "対象条件の説明/手続き簡素化/地域枠追加/財源説明/一時停止/なし",
  "fairness_perception": 0,
  "policy_fatigue": 0
}
```

ここまで入ると、単なる未来予測ではなく「制度の副作用診断」になる。

### 3. 調整ループ

LLM政策探索を入れる場合、施策を増やし続けるだけでは弱い。重要なのは、悪化した指標を見て、施策を修正・縮小・一時停止・説明強化できること。

推奨する調整アクション:

- maintain: 維持
- amend: 対象条件や給付額を修正
- sequence: 実施順序を変える
- explain: 事前説明や対象外説明を強化
- localize: 地域・属性別に分ける
- simplify: 手続きを簡素化
- pause: 一時停止
- rollback: 撤回
- compensate: 対象外層への補完策を入れる

政策プランナーは「新しい施策を考える」だけでなく、次のように動く。

1. 悪化している集団を特定する。
2. 悪化理由を、対象外感、財政不安、手続き疲労、強制感、地域差などに分類する。
3. 既存施策を修正するか、新規施策を追加するか、撤回するかを選ぶ。
4. 次ステップで反応が改善したかを見る。

この調整ループがあると、発表でこう言える。

> 制度設計で本当に重要なのは、最初から完璧な制度を作ることではありません。制度を出したあと、誰が不満を持ち、誰が離脱し、どこで分断が生まれたかを見て、炎上や退職や出生意向の低下が起きる前に調整できることです。

### 4. 二極化の見せ方

二極化は平均値では見えない。子ども希望指数や希望率の平均が上がっていても、一部の層が危険側へ落ちることがある。

見るべき分布:

- 希望率の平均
- 危険率の最大集団
- 属性別の希望格差
- 対象者と非対象者の差
- 都市と地方の差
- ケア責任あり/なしの差
- 所得・住居安定度別の差
- 前ステップから悪化した人数

UIでは、SUMMARYに平均だけを出すのではなく、次の小さな警告枠を置くとよい。

```text
分断警告
対象外反発: 高
悪化集団: 地方/ケア責任あり/非対象若年層
調整候補: 対象条件説明、手続き簡素化、補完支援
```

### 5. 施策投入上限

推奨値:

- 1ステップの総アクティブ施策: 最大12件
- 1ステップの新規施策: 最大4件
- 1カテゴリの施策: 最大3件
- LLM政策プランナーの提案: 最大5件
- 実際に採択する施策: 最大2件

この上限があると「大量投入で勝った」ではなく「制約下で構造持続が効いた」と言える。

### 6. 評価指標

若者・子育てデモ:

- 希望 / 中立 / 注意 / 危険
- 子ども希望指数
- 家族形成対象年齢の子ども希望指数
- 制度信頼
- 未来経路開放度
- 構造支援実感
- 離脱/撤退リスク

企業人事制度デモ:

- 不満者率
- 退職リスク
- モチベーション
- 採用魅力度
- 管理職反発
- 対象外反発
- 制度疲労
- 実装負荷

自治体制度デモ:

- 住民納得度
- 対象外反発
- 利用率
- 行政負荷
- 財政不安
- 若者定着
- 子育て実行可能性

### 7. 100年プランの扱い

100年は個人マップではなく、次のように扱う。

- 0から40年: 個人エージェントと世代代表をマップ表示する
- 45から100年: コホート統計、制度記憶、人口構造、信頼継承として表示する

これで122歳問題を避けられる。

## 実装順序の推奨

1. プロンプトに対称ルールを追加する。
2. `scenario_context` を全シナリオで同じ形式にする。
3. 施策イベントの表示上限または要約器を入れる。
4. `HP07` の名称と影響方向を修正する。
5. イベントデータに仮説管理カラムを追加する。
6. 12ステップの短いスモーク実行で、比較条件と指標の出方を見る。
7. 83ステップの本番実行を回す。
8. 最後に `policy_search_no_sustain` / `policy_search_with_sustain` を追加する。

## 勝ち筋としての説明

強い言い方:

> 中学生が考える制度設計は「お金を配る」「支援を増やす」で止まりがちです。このシミュレーションは、支援そのものではなく、支援が本人に届くか、信じられるか、対象外反発を生むか、財政不安を増やすか、時間が経って制度記憶として残るかまで観測します。

> さらに、LLMが施策を考え続けるだけでは不十分です。探索空間に「構造持続」という概念がある場合とない場合で、同じLLMでも到達する社会状態が変わる。ここがこのデモの創発性です。

> つまりこれは政策のチャットボットではなく、制度の打ち方、順番、伝え方、副作用、離脱リスクを事前に見るための制度設計スタジオです。

## 判定

現状のままでもデモとしては強い。ただし優勝を狙うなら、次の修正は優先度が高い。

- 施策投入量の公平化
- 全シナリオの `scenario_context` 整備
- プロンプトの対称性強化
- 未来イベントの仮説管理
- 100年表示のコホート化

この5つを入れると、「LLMでそれっぽい未来を出した」ではなく、「制度設計の探索空間を比較できるプロトタイプ」として見せられる。

## 2026-05-05 実装メモ

このレビュー後、次の項目を実装した。

- 生成プロンプトに、支援があっても届かない、対象外になる、手続きが重い、制度不信や財政不安で改善しない場合を明示した。
- 生成プロンプトに、二極化、対象外反発、政策疲労、強制感、実装負荷を観測する指示を追加した。
- LLM出力に `side_effect`、`adjustment_request`、`fairness_perception`、`policy_fatigue` を追加できるようにした。
- 全シナリオに `scenario_context` を追加し、利用可能な政策チャネル、届き方、制約、利用できないものを同じ形式で渡すようにした。
- 同時に見える政策イベントを最大12件に抑え、超過分は `POLICY_SUMMARY` として情報過多・実装負荷・対象外反発の観測対象にした。
- `HP07 希望3体以上観測ゲート` を `希望不足時の条件監査` に変更し、アウトカム誘導ではなく説明可能性と副作用監査のイベントにした。
- 未来感情マップには既存の副作用・調整パネルがあり、二極化、対象外反発、政策疲労、強制感、財政不安、実装負荷、悪化しやすい層、調整候補を表示できることを確認した。
